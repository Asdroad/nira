# NIRA — платформа закупок и продаж

Первая рабочая локальная версия по подготовленному дизайну. Данные сохраняются в базе, а доступ проверяется сервером. Ключи внешних сервисов для запуска не нужны.

## Запуск на Windows

Нужен Python 3.12 или новее. В терминале из папки проекта:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

Откройте http://127.0.0.1:8000/app/ и создайте организацию. Приложение начинает с пустой базы. В другом терминале запустите обработку документов:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/worker.ps1
```

Первый запуск устанавливает зависимости и применяет миграции. Каждый следующий запуск применяет новые миграции. `Ctrl+C` останавливает соответствующий процесс. База находится в `.data/nira.db`, оригиналы файлов — в `.data/files`. Удаление этих файлов удалит локальные данные. Не храните рабочую базу в Git.

Настройки можно скопировать из `.env.example` в `.env`. Основной ИИ использует OPENROUTER_API_KEY из .env. Поиск и локальный OCR работают без ключей. Для изменения ключа или модели перезапустите сервер и исполнитель. Документация API: http://127.0.0.1:8000/api/docs. Проверка состояния: http://127.0.0.1:8000/api/health.

## Основной ИИ

Добавьте `OPENROUTER_API_KEY` в локальный `.env`. Модель задаётся `NIRA_AI_MODEL` (по умолчанию `openai/gpt-6-luna`). Перезапустите приложение и исполнитель. Секрет хранится только в окружении сервера. Повторные анализы одинаковых данных используют готовый отчёт; обновление поиска анализирует только изменённые источники. Расчётные лимиты по умолчанию — $0,02 на запрос и $0,10 на новые анализы одной задачи.

Во вкладке «ИИ и документы» загружайте КП/прайсы файлами. После утверждения требований и чтения файлов ИИ автоматически разбирает документы, сверяет обязательные условия, готовит объявление и письмо. Первичный анализ также запускает поиск по подготовленной фразе; поиск читает ограниченное число открытых сайтов и страниц контактов. Подтверждённые на странице названия и email используются для создания кандидатов и черновиков. Без подключённой почты письма остаются черновиками.

Для покупателя вкладка «Сравнение КП» показывает условия в едином виде, цитаты, причины исключения и рекомендацию. Неизвестные цена, налоги, доставка, срок или оплата не превращаются в нулевые значения. CSV содержит сравнение, полный отчёт — причины, цитаты и вопросы. Для поставщика ИИ описывает загруженное собственное предложение и готовит обращения заказчикам; исходные КП прикрепляются к черновикам. Ручное заполнение формы КП убрано из основного сценария.

## Локальный OCR и поиск

Для настройки OCR после создания окружения запустите `scripts/setup-ocr.ps1`. Нужен 7-Zip; системная установка Tesseract и права администратора не требуются. Сканы PDF распознаются фоновым исполнителем, которого запускает `scripts/worker.ps1`. Старые документы со статусом «Нужен OCR» можно открыть и повторно обработать.

Поиск запускается из карточки задачи после утверждения требований. Выберите вкладку «Поиск», фразу и источники. Доступны интернет через DuckDuckGo и публичные закупки ONLINECONTRACT, включая фильтр действующих процедур. Результаты сохраняются со ссылками; состояние обновляется автоматически. Почта и модель ИИ для этого не нужны. Два остальных проверенных сайта не предоставляют обнаруженного открытого каталога: ограничение отображается в выдаче и разделе интеграций.

## Что работает

- Регистрация организации, вход, выход, роли, приглашение до пяти сотрудников по одноразовой ссылке, отзыв доступа. Владелец учитывается отдельно.
- Профиль организации: заказчик, поставщик или оба варианта; сферы деятельности, регионы, описание.
- Задачи закупки и продажи, ответственные, версии требований, контрагенты с источниками, каталог, история действий.
- Загрузка PDF, DOCX, XLSX и CSV, фоновое извлечение текста и структуры, локальный OCR русских и английских сканов PDF, координаты страниц/ячеек, скачивание оригиналов. Нераспознанные страницы отмечаются для проверки.
- ИИ-разбор КП и прайсов разных форматов, проверка источников, сравнение и рекомендации, объявления и шаблоны писем, поиск контактов и автоматические черновики, экспорт таблицы и объяснений. Для модели нужен ключ OpenRouter.
- Поиск в интернете и публичных закупках ONLINECONTRACT: фоновый запуск, результаты со ссылками, история поисков, ограничения каждого источника, квоты и проверка версии требований.
- Совместимость с ранее внесёнными и версии КП; сравнение по полной стоимости или сроку, подтверждённые источники, выбор предложения.
- Черновики обращений и согласование конкретного содержания. Редактирование требований или письма отменяет прежнее согласование.
- Ручной импорт писем, отчёты и CSV; показатели вычисляются из записей, а не из демонстрационных чисел.
- Общие квоты организации и выбор периода будущей оплаты: месяц, квартал, год. Во всех вариантах квоты обновляются ежемесячно.

## Что подключается следующим этапом

Коммерческий поисковый API, OAuth/IMAP/SMTP почты, публикации на закупочных площадках, структурное распознавание сложных таблиц, реальный платёжный провайдер и подтверждённые платежи. OpenRouter подключён, реальный разбор и сравнение тестовых КП проверены. Пилотный поиск уже доступен; отправка и оплата отвечают «сервис не подключён». Они не увеличивают показатели и не продлевают доступ.

Общий администратор платформы, тарифные цены, восстановление пароля, подтверждение email, MFA, управление секретами, промышленная инфраструктура и её проверка ещё не реализованы. Эта версия предназначена для локальной разработки. Переключение настроек на `production` само по себе не делает её готовой к публичному запуску.

## Структура

| Папка | Назначение |
|---|---|
| `frontend/` | Рабочая копия интерфейса, связанная с API |
| `backend/app/` | Сервер, модели, права, обработчик документов |
| `backend/migrations/` | Версионируемые миграции Alembic |
| `backend/tests/` | Проверки бизнес-правил и изоляции организаций |

## Проверка

```powershell
powershell -ExecutionPolicy Bypass -File scripts/test.ps1
```

Тесты создают отдельную временную базу и файлы. Проверяются права, чужие данные, пять мест, приглашения, согласования, версии КП, доставка, квоты, реальные форматы документов и экспорт. Зафиксированные версии зависимостей находятся в `backend/requirements.lock.txt`.

SQLite используется для разработки. Для сервера предусмотрены PostgreSQL, те же модели и Alembic. Перенос локальных данных, нагрузочные испытания и проверка PostgreSQL должны выполняться отдельным этапом перед размещением приложения.
